Qwen2.5-VLとSAM2.1の視覚特徴統合方法

モデル規模と設計方針: 今回設計するLISA改統合モデルでは、まずQwen2.5-VL-3Bをベースに動作確認し、順次7B、最終的には72Bモデルへとスケールアップする方針とのことです。幸いQwen2.5-VLの3B・7B・72Bは基本的なアーキテクチャが共通であり、視覚情報の扱い方も一貫しています ￼。したがって統合方法自体は全サイズで概ね共通で使えるように設計できます（小さいモデルでは計算資源上、トークン数や一部構成を簡略化する可能性はありますが、基本は同じ手順で問題ありません）。以下では、Qwen2.5-VLの視覚エンコーダ部分とSAM2.1を組み合わせて視覚特徴を統合する最適策を提案します。

統合戦略の概要: LISA論文の手法にならい、SAMの強力な画像エンコーダをQwen側に組み込みます ￼。具体的には、Qwen2.5-VLのビジョンバックボーンをSAM2.1の画像エンコーダ（ViT）に置き換え、その出力する視覚特徴をLLMに入力します。LISAではLLaVA-7Bの視覚エンコーダをSAM (ViT-H) に差し替え、入力に対しSAM由来のパッチ埋め込みをLLMに取り込むよう調整していました ￼。LISA改でも同様に、Qwenの画像処理部分をSAM2.1ベースに差し替えるのが自然です。SAM2.1は画像・動画両対応のViTベースモデルですが、まず画像に限定し、SAM2.1のViTが出力する画像埋め込み（高次元特徴マップ）を活用します。

視覚トークン数と形状: Qwen2.5-VLは画像を内部で可変長のトークン列として扱える設計です。デフォルトでは1画像あたり最小4トークン～最大16384トークンまで対応しており、解像度やシーンに応じて動的にパッチ数を調整します ￼。このため固定32トークンなどの制約は無く、SAMのViTから得られる大量のパッチ特徴（例: 64×64=4096トークン）もそのまま投入可能です。Qwenでは画像入力時にと等の特別なトークンで囲んだビジュアルトークン列をシーケンスに挿入し、モデル内部でViTにより画特徴を算出→テキストと一緒にトランスフォーマーで処理という流れになっています ￼ ￼。そこで、QwenのViT部分をSAM2.1のViTに置換し、出力埋め込みをQwen標準の方法でトークン列に組み込むように調整します。Qwen2.5のvision_configを見ると、隠れ次元1280・パッチサイズ14などSAM ViT-Hに近い設定になっており、これはSAM ViT-H (hidden=1280, patch=16)とのギャップが小さいことを示唆します ￼。多少のパッチサイズ差（14 vs 16）はありますが、Qwen側は動的解像度対応のため大きな問題にはなりません。実際Qwen2.5-VLはマルチモーダル強化の一環でウィンドウ注意型のViTを内蔵していますが ￼、ここをSAM2.1相当のViTに換装し、その重みを初期値として使う形です。これにより、高精度なセグメンテーションに必要な細かな視覚特徴をLLMに取り込むことができます。

特徴次元の整合: SAMのViT出力次元とQwenの言語モデル埋め込み次元をマッピングする必要があります。Qwen-7Bのテキスト隠れ次元は3584ですが、vision_config上は画像埋め込み1280次元になっています ￼ ￼。おそらくQwen内部ではViT出力1280→LLM埋め込み3584へ線形射影する層を持っています（他のマルチモーダルモデル同様に） ￼。従って、SAM2.1 ViTを使う場合も同様の全結合射影を用意し、出力トークンそれぞれ1280次元ベクトルを3584次元に変換してからLLMに渡します ￼。LISAではこの射影は既存のLLaVAのものを再学習させたと推測されますが、LISA改でも射影層は学習可能とし、SAMから出た特徴がLLM内部表現空間で最適に活用されるよう調整します。まとめると、**「画像→SAM ViT(1280次元特徴)→線形層(1280→3584)→LLMデコーダに投入」**というパイプラインになります。

マスク出力の統合: 上述の流れでLLM（Qwen）が画像の内容を理解・推論できるようになったら、セグメンテーションマスク生成機能を組み込みます。ここではLISA方式のembedding-as-maskパラダイムを踏襲します ￼ ￼。すなわち、LLMのボキャブラリにを追加し、これが生成された際には対応する隠れベクトルをマスク解読に用いる仕組みです。具体的には、統合モデルの出力にが現れたら、そのベクトルをMLP層(f)で変換し（例えば1280→256次元）、SAM2.1のマスクデコーダへ入力します ￼。一方、画像全体の埋め込み（SAM ViT出力）は既に取得済みなので、これもデコーダに供給します ￼。SAM2.1のマスクデコーダは、元々画像埋め込み + プロンプト埋め込み（ポイントやボックス、マスクなど）から対象領域を推論するモジュールです ￼ ￼。LISA改ではこのプロンプト埋め込みにLLM由来の埋め込みを使う形になります。図で示せば、SAM2.1 ViT (画像特徴)とLLM埋め込みを結合してデコーダに入れ、マスク画像を出力する流れです ￼ ￼。このアーキテクチャはLISA論文Fig.3と同様で、視覚部分(SAM)と言語部分(LLM)の役割を明確に分担させています ￼。Qwen2.5-VLは言語生成能力に長けていますので、画像認識はSAMに任せ、理由説明やマルチターン対応などはLLMが担う形です。統合モデルでは、例えば質問内容に応じてLLMが回答文と言語的推論を生成しつつ、セグメントすべき対象に差し掛かったところでを出力、対応するマスクがSAMデコーダから返される、といった応答が可能になります。

Frozen戦略とLoRA: 学習に際しては、LISAのようにSAMの画像エンコーダは凍結し、LLM部分も元の汎用能力を損なわないようLoRAで微調整する方針が適しています ￼。LISAではSAM ViTを固定し、マスクデコーダは全層学習、LLMはLoRAで微調整という効率的手法で良好な結果を得ています ￼。LISA改でも、まずSAM2.1の強力な事前学習ウェイトを活かしつつ（凍結して）使い、LLM側は視覚情報統合に必要な最小限のパラメータを学習させることで、大規模モデル(72B)でも現実的な計算量でファインチューニングできるようにします ￼。特に72BではVRAM消費が莫大になるため、パラメータ更新箇所を絞ることが重要です。段階的な動作確認（3B→7B→72B）では、小さいモデルでまず統合コードが正しく動きLossが下降するかをチェックし、次第にモデルと画像トークン数を増やしていきます。Qwen2.5-VLは高解像度画像や長時間動画まで扱える設計ですが ￼ ￼、巨大モデルでは計算負荷とのトレードオフになります。そこで例えば3Bや7Bでは画像を縮小（例：512×512）してトークン数を減らす、72Bで本番運用時には高解像度対応にする、といった柔軟も考えられます。いずれにせよ、根幹部分の統合アーキテクチャは共通であり、SAMの視覚的知見とQwenの言語的知見をシームレスに結合する形でLISA改を構築します。

## 実装修正方針（2025年8月1日追記）

現在の実装と上記要件のギャップを解消するため、以下の修正を実施します：

### 修正方針1: SAM2.1 ViTによるQwenビジョンエンコーダの完全置換（最優先）
**現状の課題**: QwenとSAMがそれぞれ独自のビジョンエンコーダを使用しており、真の統合になっていない
**修正内容**:
- QwenのビジョンエンコーダをSAM2.1のimage_encoderに完全置換
- SAM ViT出力（64×64×1280）をQwenが期待するトークン列形式に変換
- 画像処理を完全にSAM2.1に委譲し、統一された視覚特徴を使用

### 修正方針2: 正しい次元マッピング実装（1280→3584）（高優先）
**現状の課題**: 現在は256次元への投影のみで、Qwenの期待する次元（3584）に合っていない
**修正内容**:
```python
# SAM ViT出力(1280) → Qwen LLM入力(3584)の段階的投影
self.vision_to_llm_projector = nn.Sequential(
    nn.Linear(1280, 2048),
    nn.LayerNorm(2048),
    nn.GELU(),
    nn.Dropout(0.1),
    nn.Linear(2048, 3584)
)
```

### 修正方針3: LISA準拠のembedding-as-mask完全実装（中優先）
**現状の課題**: 簡易的なmask_headでマスク生成しており、SAM2.1の公式デコーダを活用していない
**修正内容**:
- `<SEG>`トークンの隠れベクトルをSAM2.1のmask_decoderに正しく渡す
- SAM2.1の公式APIを使用してマスク生成
- 複数マスク対応（GSVA準拠）

### 修正方針4: 学習安定性の更なる向上（低優先）
**実装内容**:
- 段階的学習（投影層のみ→デコーダ追加→全LoRA）

### 修正方針5: コードのクリーンアップ（低優先）
