# Qwen2.5-VL-3B + SAM2.1 統合モデルの最適構造への修正提案

## 現状統合モデルの評価

現在の統合モデル実装をコードおよび記述から判断すると、以下の構造・手法が採用されています：

* **統合手法**: 画像特徴は**Q-Former経由**でLLMに取り込まれています。これはBLIP-2に類似したアプローチで、SAM2.1の画像エンコーダ出力を軽量Transformer（Q-Former）による**クエリトークン集約**で32個程度の視覚トークンに変換し、Qwen2.5-VL-3Bの言語モデル部分へ入力しています。したがって、**Q-Formerベースの視覚特徴プロジェクション**が主な統合手法になっています（READMEの説明通り） 。

* **段階的統合の傾向**: モデルの**セグメンテーション出力はLLMとは独立**しており、ユーザから与えられるポイント（`point_coords`, `point_labels`）をSAMのマスクデコーダに入力してマスクを生成しています。つまり、**画像エンコーダ＋LLMによるテキスト生成**と、**画像エンコーダ＋ポイント指定によるマスク生成**が**並列的**に行われており、現状ではLLMが直接マスク生成を指示しているわけではありません。これは**段階的プロセス統合**（パイプライン型）の色合いが強く、LLMとセグメンテーションがエンドツーエンドで結合されていない状態です。

* **SAM2.1の統合範囲**: **画像エンコーダとマスクデコーダの両方**が組み込まれています。コード上で`SAM2.1`のViTエンコーダを用いて画像特徴を抽出し（`sam_encoder`）、ポイントプロンプトがあれば**SAM2.1のマスクデコーダ**でマスク推論（`sam_decoder`）を行っています。従って、エンコーダ統合に留まらず**マスクデコーダまで含めた結合**ですが、先述の通りマスク生成はLLM出力と連携せず**ユーザ入力のプロンプトに依存**しています。

* **Qwen内蔵ViTの扱い**: Qwen2.5-VL-3Bの本来のビジョンエンコーダ（ViT）は**使用されておらず**、**SAM2.1のViTエンコーダ**に差し替えられています（READMEに「モンキーパッチ: Qwenの視覚エンコーダーをSAM2.1に置換」と記載）。実装中では、Qwenのモデルロード後に`vision_tower`等の属性を上書きしてSAMのエンコーダを組み込んでいるか、あるいはLLMへの画像入力処理そのものを独自に構成し、Qwenの視覚エンコーダ部分はバイパスされていると推測できます。要するに**QwenのViTバックボーンは使わず**、**SAM2.1の高精細ViT特徴**を活かす構造になっています。

以上より、現在の実装は\*\*「SAMエンコーダ + Q-Former + Qwen-LLM」**というアプローチAに近く、セグメンテーション出力はLLMとは別段階で処理する**段階的統合**の形式です。これを踏まえ、以下に**最適統合モデル構造へ改良するための具体的な修正方針\*\*を示します。

## 最適統合構造への修正方針

目指すべき最適構造は、**LLMとセグメンテーションが真に一体化したエンドツーエンドモデル**です。具体的には、LLMが出力中に直接マスク生成をトリガーできるようにし、テキストとマスクの双方を**単一のモデル**で同時に生成できる構造を構築します。これには以下の修正・追加が必要です。

### 1. 特殊トークンによるマスク生成の組み込み

まず、LLMの**語彙にセグメンテーション用の特殊トークン**を追加し、これを介してマスクデコーダを駆動する仕組みを導入します。先行研究LISAでは語彙に`<SEG>`トークンを新設し、**“embedding-as-mask”**パラダイム（埋め込みをそのままマスクに対応させる手法）を提案しています。我々も同様に`<SEG>`（任意の名前で可）トークンを追加し、**LLMの最終隠れ状態**をマスクデコーダへの**クエリベクトル**として使用します。実装手順は以下の通りです。

* **トークン追加と埋め込み拡張**: Qwen2.5-VLのトークナイザとモデルの語彙に、新たに`"<SEG>"`トークン（および必要なら`"<IMG>"`等の画像トークン）を追加します。Hugging Face Transformersを利用している場合、`tokenizer.add_special_tokens(...)`で追加し、その後`model.resize_token_embeddings(len(tokenizer))`を呼び出してモデルのエンベッディング行列を拡張します。コード例を示します。

```python
# model 初期化直後（create_sam_qwen_model内など）で特殊トークンを追加
seg_token = "<SEG>"  # セグメンテーション用特殊トークン
tokenizer.add_special_tokens({"additional_special_tokens": [seg_token]})
qwen_model.resize_token_embeddings(len(tokenizer))
# 追加したトークンのIDを保持（後で出力検知に使用）
model_config.SEG_TOKEN_ID = tokenizer.convert_tokens_to_ids(seg_token)
```

上記により、LLMは新しいトークン`<SEG>`を出力可能になります。このトークンは\*\*「ここでマスク生成を行う」\*\*ことをモデルに示す目印となります。

* **LLM出力とマスクデコーダの連携**: モデルの`forward`処理を改修し、**LLMの生成出力中に`<SEG>`トークンが出現した場合**に対応するマスクを生成するようにします。具体的には、テキスト生成完了後に生成系列をチェックし、`SEG_TOKEN_ID`の出現位置を特定、その位置におけるLLM最後の隠れ状態ベクトルを取得します。このベクトルこそが**対象物のマスクを表現する埋め込み**です。このベクトルを所定の次元に射影（必要であれば線形層などでSAMデコーダのクエリ次元に合わせる）し、SAM2.1のマスクデコーダにクエリとして入力します。疑似コードを示します。

```python
def forward(self, image, question):
    # 1. 画像特徴抽出（SAMエンコーダ）と視覚特徴プロジェクション（Q-Former等）
    image_feats = self.sam_encoder(image)                        # SAM ViT特徴
    vision_tokens = self.visual_projector(image_feats)           # Q-Former等で視覚トークン取得

    # 2. LLMテキスト生成（画像トークン＋質問を入力）
    # Qwenモデルに画像とテキストを与えて回答生成。monkeypatchによりvision_tokensが利用される前提。
    inputs = tokenizer(question, return_tensors="pt").to(device)
    output_ids = self.qwen_model.generate(
        **inputs,
        images=image,              # Qwenがimages引数で画像を受け取れる場合
        max_new_tokens=128,
        do_sample=False
    )
    generated_text = tokenizer.decode(output_ids, skip_special_tokens=True)

    # 3. 特殊トークン<SEG>の出現チェックとマスク生成
    mask = None
    if self.config.SEG_TOKEN_ID in output_ids:
        # <SEG>トークンの位置を取得（ここでは最初の出現位置を使用）
        seg_index = (output_ids == self.config.SEG_TOKEN_ID).nonzero(as_tuple=True)[1].item()
        # その位置に対応するLLM最終レイヤーの隠れ状態を取得
        outputs = self.qwen_model(
            **inputs,
            images=image,
            output_hidden_states=True,
            return_dict=True
        )
        # hidden_states[-1]: [batch, seq_len, hid_dim] の最終層隠れ状態
        seg_embed = outputs.hidden_states[-1][0, seg_index, :]  # shape: (隠れ次元,)
        # 必要に応じて次元変換：seg_embed -> mask_query_embed
        mask_query = self.mask_query_proj(seg_embed)  # e.g., Linear layer to decoder dim
        # SAM2.1マスクデコーダにクエリと画像エンコーダ出力を入力してマスク予測
        mask = self.sam_decoder(image_feats, mask_query)  # mask: [H, W] or [1, H, W] binary mask tensor

    return {"generated_text": generated_text, "mask": mask}
```

上記のポイントをまとめると、**LLMの出力系列内に`<SEG>`トークンがあれば、その埋め込みからマスクを一体生成**する処理を追加しています。これによりモデルはテキスト回答中にマスク出力を**内部で挿入**できるようになります。「画像中の○○をセグメントして」という質問に対し、モデルは例えば「承知しました。<SEG> が対象領域です。」のように内部シーケンスを生成し、`<SEG>`に対応する実際のマスクを出力として返すことが可能となります（ユーザには`<SEG>`トークンは表示せずマスク画像のみ提示）。

* **Pointプロンプト依存の解消**: 上記改修に伴い、モデルのインタフェースから明示的な`point_coords`等の引数に頼らずともマスク生成ができるようになります。コード上は`forward`のシグネチャから`point_coords`/`point_labels`を省略し、**質問文と言語コンテキストだけでセグメンテーション要求を完結**させます。必要であれば後方互換のため`point_coords`をオプション引数として残し、「明示的ポイント指定がある場合は従来通りその点に対するマスクを生成し、無い場合はLLM出力トークンに応じたマスクを生成」という分岐も可能です。しかし最終的には特殊トークンに基づく自律的なマスク生成に移行することが望ましいです。

* **複数マスク出力への拡張**（将来検討）：現在は単一の`<SEG>`トークンで1つの領域マスクを生成する実装ですが、ユーザの問いによっては複数対象の同時セグメンテーションや、該当物体が存在しないケースもあります。これに対してはCVPR 2024の**GSVA**研究で提案されたように、**複数の`<SEG>`トークン**や\*\*\[REJ]トークン\*\*（対象なし=拒否応答）を導入する方法が考えられます。例えば3つの対象を指示する文に対し、モデルが`<SEG><SEG><SEG>`と3つの埋め込みを生成し、それぞれから3枚のマスクを出力する、といった動作です。これは高度な拡張機能になりますが、基本となる単一`<SEG>`トークンによる実装が完成した後に段階的に組み込むことが可能です。

### 2. モデルアーキテクチャの見直し（エンコーダ統合と投影層）

特殊トークンによるマスク統合に加え、視覚エンコーダとLLMの結合部についても最適化の検討が必要です。ただし、大枠では現状の**SAMエンコーダ + Q-Former + Qwen-LLM**の流れを維持しつつ、以下のポイントを調整する形で十分対応可能です。

* **SAMエンコーダの活用方法**: 現在モンキーパッチでQwenのViTをSAM2.1のViTに置換していますが、**エンコーダの出力特徴量が非常に多次元・高解像度**になる点に留意する必要があります。SAM2.1のViT（Hieraアーキテクチャ）は1024×1024入力に対して数万～十数万のパッチ埋め込みを出力する可能性があります。このままではLLMに直接与えるにはトークン数が多すぎるため、**何らかの圧縮/間引き**が必要です。現状導入済みの**Q-Former**はまさにその役割を果たすモジュールであり、例えば32個程度の学習クエリに対してSAMエンコーダ特徴をアテンションし、**LLMが扱いやすい数十トークンに凝縮**します。したがって、**Q-Formerは引き続き利用**する方針で問題ありません。コード上も`visual_projector`として実装済みであり、`USE_QFORMER=True`時はQuery側Transformerを用いる設計になっています。この部分はそのまま活かし、必要に応じてクエリ数（`NUM_QUERIES`）を調整してください（デフォルト32で十分ですが、対象タスクに応じて増減可能です）。

* **直接統合（オプション）**: 将来的にQ-Formerを介さず直接SAM特徴をLLMに渡すことも検討できます。Qwen2.5-VLは**動的長さの視覚トークン入力**を処理できるアーキテクチャ（Naive Dynamic Resolution）を持つため、例えばSAMエンコーダ出力を一定ストライドで間引いて数百～千程度のトークンに圧縮し、線形層で次元変換してLLMに与える、という方法も理論上可能です。現時点では大規模改変となるため優先度は低いですが、**VisualProjectorを線形プロジェクタに切り替える**設定（`USE_QFORMER=False`）もコード上サポートされているようなので、必要に応じて実験可能です。どちらにせよ、**LLMが受け取る視覚埋め込みの次元**はQwenの隠れ状態次元（例えば\$\sim\$4,000くらい）に揃える必要があるため、Q-Former出力あるいは線形射影出力のサイズを合わせる処理は忘れずに実装してください。

* **射影層と結合位置**: 上述の`mask_query_proj`のように、LLMの隠れ状態ベクトルをマスクデコーダに渡す際、必要なら**小さな射影ネットワーク**を挟みます。SAM2.1のマスクデコーダでは、ポイントやボックスなどの**スパースプロンプト埋め込み**を受け取るための重みが定義されています。LISA実装ではLLM埋め込みをそのまま活用できるよう、次元を合わせた線形層を用いていました。本統合でも`seg_embed (dim_d) -> mask_query (dim_e)`へのAffine変換を1層追加し、SAMデコーダの期待する埋め込み次元（例えば256やpromptエンコーダ次元）に合わせてください。これによりLLM側の出力埋め込みを違和感なくデコーダに投入できます。

### 3. エンドツーエンド学習のセットアップ

アーキテクチャが整ったら、**テキスト生成とマスク生成を共同最適化する学習**を行う必要があります。モデルが新たな構造を十分活用できるように、以下の学習戦略をとります。

* **パラメータ凍結とLoRAによる効率調整**: 大規模モデルの微調整では、元の知識を保持しつつ新機能を付与するために一部凍結と軽量学習が有効です。**SAM2.1の画像エンコーダ（ViT部分）は原則凍結**し、既存の強力な視覚表現をそのまま利用します。マスクデコーダは新タスクへの適応のため**学習可能**とし（ただし事前学習済み重みで初期化し微調整程度に留める）、LLM側は**大部分を凍結してLoRAによる微調整**を適用します。LoRA (Low-Rank Adaptation) はTransformerの重みの一部に低ランクの学習可能差分を挿入する手法で、LISAやGSVAでも**LLMをフルチューニングせずLoRAで効率的に適応**させたと報告されています。コード上はHuggingFace PEFT等を利用し、QwenモデルにLoRAモジュールを組み込む実装が考えられます。例:

```python
# SAMエンコーダを凍結（学習時に勾配を流さない）
for param in sam_encoder.parameters():
    param.requires_grad = False

# QwenモデルにLoRAを適用（PEFTライブラリを利用する場合）
from peft import LoraConfig, get_peft_model
lora_config = LoraConfig(
    r=8, lora_alpha=16, target_modules=["q_proj", "v_proj"], lora_dropout=0.05,
    bias="none", task_type="CAUSAL_LM"
)
qwen_model = get_peft_model(qwen_model, lora_config)
print("Trainable params: ", qwen_model.print_trainable_parameters())
```

上記ではQwenのAttention層の`q_proj`（Query投影）や`v_proj`（Value投影）をLoRA化し、学習可能パラメータを大幅削減しています（他の層に適用しても良いですが、必要最低限に留める方が安定します）。出力として「Trainable params: **0.x%**」のように全体に占める割合が表示され、ほぼ<1%に抑えられるはずです。これにより**LLMの言語生成能力を保持しつつ**、新たな出力様式（マスク生成）に対応する調整だけを効率よく行えます。

* **マルチタスク損失の設定**: 学習時には**テキスト生成タスク**と**マスク予測タスク**の両方に対して損失関数を定義し、合同で最適化します。具体的には、テキスト部については標準的な言語モデルのクロスエントロピー損失（チャット履歴に対する次トークン予測損失）を計算し、マスク部についてはIoUベースのDICE損失やピクセル単位のバイナリクロスエントロピー（BCE）損失を計算します。それらを適切な重みで和として**合成損失**とし、逆伝播で勾配を更新します。このとき、テキスト損失とマスク損失の比重を調整して、言語応答品質を損なわない範囲でマスク精度を高めるのがコツです（例えばテキスト:マスク = 1:1や1:0.5などデータによって調整）。

* **学習データの準備**: この統合モデルを学習させるには、**画像＋テキスト＋マスク注釈**のペアからなるデータセットが必要です。幸い、一般物体のセグメンテーションタスクにはCOCOやRefCOCOなど大規模データセットがありますので、まずは**RefCOCO/RefCOCO+**等の**参照表現セグメンテーション**データを用いると良いでしょう。これらは「与えられた文が指す物体のマスク」を含むデータセットで、本モデルの目的（ユーザ指示に基づくマスク生成）に適しています。データ準備時には、質問文のフォーマットに`<SEG>`トークンの出力を期待する形で**模範解答シーケンス**を作っておきます。例えば、ある画像と言語指示に対し、模範解答を「<SEG>」とだけする（つまりテキストは何も返さずマスクだけ出力する）か、あるいは「これは<SEG>です。」のようにテキスト中にトークンを含めるか、設計次第です。LISAでは後者（文章＋<SEG>）の形式で学習させたようです。いずれにせよ、学習データ中でモデルが適切に`<SEG>`トークンを使うよう教師強制し、そのトークンに対応するマスク損失を与える必要があります。テキスト応答データ（純粋なVQAなど）も一緒に学習させることで言語能力の維持も図れます。

以上の学習設定により、モデルは**画像と言語の高次推論能力**と**ピクセルレベルのマスク生成能力**を同時に獲得できます。特に複雑な質問（例：「この料理に使われているリンゴをすべてマスクして、それらの個数は？」）に対し、まずリンゴ領域を全てマスクし（複数`<SEG>`拡張があれば対応可能）、その上で個数をテキストで回答するといった**一貫した推論**も可能となります。これこそが最終的に目指す**汎用マルチモーダル基盤モデル**の姿であり、提案する修正によりその実現に近づくことができます。

### 4. テストと応答フォーマットの調整

実装後の注意点として、**モデルの出力制御**と**インタフェース**を適切に調整する必要があります。

* **出力シーケンスから特殊トークンを除去**: モデルが生成したテキスト中に`<SEG>`トークン（や将来的に`<SEG><SEG>`等複数）が含まれる場合、ユーザにそのまま表示するのではなく、**対応するマスク画像に置き換えて提示**する工夫が必要です。対話システム上はプレースホルダとして扱い、回答文字列からは取り除いておくと良いでしょう（上記コードでも`skip_special_tokens=True`でデコードしているのはそのためです）。こうすることでユーザには自然な文章とマスク結果が返されます。

* **プロンプト設計**: 推論時には、モデルが画像入力を認識できるよう適切なプロンプトを与える必要があります。Qwen2.5-VLの場合、画像自体を与える際にテキスト側で`<Image>`や類似のトークンを差し込む仕様があるかもしれません（モデルカード上は内部で処理される可能性がありますが）。monkeypatch実装では`images=`引数で直接渡しているようなので明示的トークンは不要かもしれませんが、内部的には画像位置を示す特殊埋め込みが使われている可能性があります。必要に応じてその部分もドキュメントを確認し、適切に設定してください（例：質問文の前に`<image>`トークンIDを挿入し、それに対応して`images=image_tensor`を渡す等）。

* **モデル応答の条件分岐**: エンドツーエンド化に伴い、**質問によってはマスクを出力しない**ケースもあります。例えば純粋な画像キャプションや説明だけを求める問いでは、モデルが不必要に`<SEG>`を出力しないようにする制御が理想です。このあたりは**プロンプト工夫や追加学習データ**（マスク出力不要なQAペアも学習させておく等）で対応可能です。GSVAでは出力に`[REJ]`（拒否）トークンを導入し、対象物が無い場合に誤ってマスクを生成しないようにしました。本モデルでも、「存在しない対象には<SEG>を出さずテキストで`該当物体はありません`等と答える」といった挙動を学習させると、より堅牢な応答が可能になります。

以上、**コード修正の具体例と方針**を詳細に説明しました。まとめると:

* 現行コードの**Q-Former経由の統合**を活かしつつ、新たに\*\*`<SEG>`特殊トークンとマスクデコーダの直接連携機能\*\*を組み込む。
* **モデルの語彙と出力層を拡張**し、LLM出力埋め込みを**マスククエリ**にマッピングしてSAMデコーダからマスクを取得。
* **ポイントプロンプト不要**のエンドツーエンド推論を実現し、必要なら複数マスクや拒否トークンにも拡張可能な設計。
* **学習面ではLoRA等で効率良く**モデルを微調整し、テキスト＋マスクの複合損失で高精度な応答を得る。

この修正により、モデル構造は提案された最適統合モデルそのものになり、最新研究（LISAやGSVA等）の知見を取り入れた強力な基盤が完成します。実装後は単体テスト（`test_sam_qwen_integration.py`の拡張）で、入力画像＋質問に対し期待通り`results['mask']`と`results['generated_text']`が整合した出力を返すことを確認してください。例えば、質問「写真の中からリンゴを見つけてマスクしてください」に対し、生成テキストが「リンゴをマスクしました。」となり、対応する`mask`にリンゴ領域のマスクが含まれていれば成功です。
