Phase3Bモデル修正仕様書

修正の対象範囲と目的

本書は現行のPhase3Bモデルの設計上の問題点を洗い出し、優先的に修正すべき箇所とその修正方針を示す包括的な仕様書です。対象はPhase3Bまでのモジュールおよびアーキテクチャとし、将来計画されているPhase4以降の構成要素については直接の範囲外とします。ただし、根本的な設計改善によってPhase2/Phase4以降への拡張性も確保できるよう配慮しています。以下に主要な修正項目を列挙し、それぞれの詳細な修正内容と実装ガイドを示します。

優先修正項目一覧
	1.	BLIP-2準拠のQ-Former Forward処理再設計（テキスト入力対応） – 画像とテキストの統合表現を抽出するQuerying Transformer (Q-Former)のForward処理を再設計し、テキストトークンを入力に含められるようにします ￼。BLIP-2方式に倣い、視覚特徴とテキスト情報の効果的な結合とLLMへの接続を実現します ￼。
	2.	視覚・言語特徴の分離機構導入（Llama 4統合出力からの分岐） – 大規模言語モデル（LLM）部分（Llama 4）において画像と言語の特徴が単一の表現に融合されている問題に対処します。視覚出力と言語出力を明確に分離する機構を設計・実装し、マルチモーダル出力（例：画像中の領域マスクとテキスト解答）が同時に得られるようにします ￼。
	3.	LoRAエキスパートの統合によるマルチモーダル適応 – 基盤モデル（特にSAM由来の画像エンコーダおよびLLM）の大部分は凍結し汎用能力を保持しつつ、追加の低ランク適応 (LoRA) モジュールで新規モダリティやタスクへの適応を行います ￼。複数のLoRAエキスパートを導入し、入力モダリティに応じた動的ルーティングで特徴を融合する設計とします ￼。
	4.	セグメンテーションヘッドのマルチスケール対応強化 – セグメンテーション出力の精度向上のため、SAMのマスク生成ヘッドを改良しマルチスケール特徴を活用できるようにします ￼。具体的には、画像エンコーダの複数解像度の特徴マップを統合する補助的なマスクヘッドを追加し、細部まで高精度なマスクを生成できるように設計変更します ￼。

以下、各項目について現状の課題と修正仕様の詳細を記述します。

修正項目の詳細仕様

1. Q-FormerのForward再設計（BLIP-2準拠・テキスト入力対応）

《現状の課題》 Phase3BモデルのQ-Formerモジュールは画像特徴から固定長のクエリベクトルを抽出する役割を持ちますが、現在の実装ではテキスト入力との相互作用が考慮されておらず、画像とテキストを統合した表現学習が不十分です。また、LLM（例:Llama）への接続方法も適切に定義されていません。これにより、視覚と言語の情報を同時に扱うタスク（画像質問応答など）で性能が頭打ちになる恐れがあります。

《修正方針》 BLIP-2のQ-Formerアーキテクチャを参考に、Q-FormerのForward処理を再設計します ￼。BLIP-2ではQuerying Transformer内に画像用とテキスト用のサブモジュール（自己注意層を共有）が存在し、画像エンコーダから抽出した視覚特徴とテキストトークンの両方を入力として受け取ります ￼。これにならい、以下の点を実装します:
	•	テキスト入力の受け入れ: Q-Formerのforward関数シグネチャにテキストエンコーダからのトークン列（text_inputs）をオプション引数で渡せるよう拡張します。例えば変更後は def forward(self, image_feats, text_tokens=None) -> Tensor: のように定義し、テキストトークンが与えられた場合は内部でクエリとテキスト間のクロスアテンションやマスキングを適用します。BLIP-2では32個の学習可能なクエリベクトルを用意し、それらが自己注意で相互やり取りしつつ画像特徴とクロスアテンションする設計になっており ￼、本モデルでも同様にクエリ群と画像特徴のやり取りを実装します。加えて、テキストトークンとの相互作用はタスクに応じて制御され、例えば視覚特徴抽出段階ではクエリがテキスト情報を参照しないようマスクし、マルチモーダル表現学習時には参照できるようにするなど、BLIP-2が採用した注意マスク戦略を踏襲します ￼。
	•	LLMへの接続: 抽出されたクエリの出力（視覚特徴ベクトル群）をLLMに入力できる形式に変換します。BLIP-2では、Q-Formerの出力クエリを全結合層でLLMの埋め込み次元に射影し、これを視覚のソフトプロンプトとしてテキスト埋め込みの先頭に付加してLLMの入力列としています ￼。本モデルでも同様の手法で、得られたクエリをLLMの入力に連結する実装とします（例えばLlamaがデコーダのみのLLMであれば、射影したクエリを最初の入力トークン群とし、その後にユーザの質問テキストトークンを続けて与える）。これにより、LLM内部で視覚情報と言語情報を融合させつつ、テキスト生成や質問応答を行うことが可能となります ￼。
	•	インターフェースの詳細: 修正後のQ-Formerクラスの主要メソッドは以下のようになります（疑似コード形式）:

class QFormer(nn.Module):
    # ...（省略: 初期化など）...
    def forward(self, image_feats: Tensor, text_tokens: Optional[Tensor] = None) -> Tensor:
        """
        画像エンコーダ出力の視覚特徴 (image_feats) から、学習可能クエリとクロスアテンションにより
        固定長の視覚表現ベクトル群を取得。text_tokens が与えられた場合、適切な注意マスク戦略の下で
        クエリがテキスト情報と相互作用し、テキストに関連する視覚特徴を抽出する。
        戻り値:
            query_embeds: Tensor [N_queries, D] 抽出されたクエリ埋め込みの集合
        """
        # 実装イメージ:
        # 1. 学習済みBERT初期値の自己注意層で構成されたTransformerを内部にもつ
        # 2. 入力として image_feats と 初期クエリembedding を用意
        # 3. cross-attention: クエリがimage_featsを参照（テキストは通常ここでは参照しない）
        # 4. text_tokens がある場合、必要に応じ自己注意層でクエリとテキストを混ぜる (BLIP-2のマスク戦略)
        # 5. 出力としてクエリ埋め込み群 (query_embeds) を取得
        return query_embeds

このようにQ-Formerを再設計することで、テキスト入力に依存した視覚特徴抽出が可能となり、画像と言語のきめ細かな対応付けが実現されます。例えばBLIP-2では、Q-Formerの学習を2段階に分け、第一段階で視覚-言語表現学習（テキストに関連する視覚特徴を抽出するようクエリを訓練）を行い ￼、第二段階で凍結LLMに接続して視覚情報を解釈可能にする訓練を行っています ￼。本モデルでもPhase3BにおけるQ-Former再設計後の学習で同様のアプローチを取ることで、LLMと密接に連携した高性能なマルチモーダル表現抽出が期待できます。

2. Llama 4出力における視覚・言語特徴分離機構の設計

《現状の課題》 Phase3Bモデルでは、LLM（想定: Llama 4など）の中で視覚情報とテキスト情報が統合的に処理されており、生成結果から視覚的出力（例: セグメンテーションマスクに必要な特徴）と言語的出力（テキスト応答）の区別が曖昧です。特にLlama 4はMeta社によれば画像とテキストのトークンを単一のモデル内で「早期融合 (early fusion)」するアーキテクチャを採用しており、別個のエンコーダ・デコーダを持たずに統合的な理解を行うとされています ￼。この利点として自然なマルチモーダル理解が挙げられる一方、モデル内部で視覚と言語の表現が一体化するため、後段でそれぞれを分離して利用する仕組みが必要になります。

《修正方針》 LLM統合部に視覚・言語特徴の分離機構を導入し、モデルの出力段階で画像関連の情報とテキスト関連の情報を明確に取り出せるようにします。具体的には、以下の2点を設計に盛り込みます:
	•	トークン種別のマーキング: LLMに入力する段階で、視覚由来のトークンとテキスト（言語）由来のトークンを区別できるよう工夫します。例えば、入力シーケンス上で画像トークン（Q-Formerから得た視覚クエリを射影したもの）とテキストトークンを結合する際に、画像トークンに専用のセグメントIDや埋め込みオフセットを付与する方法が考えられます。Llama 4自体は内部で統合処理を行いますが、こちらでトークンの種別情報を付加しておけば、モデルの最終層の隠れ状態を解析することで「どの部分が視覚情報に対応するか」を取り出しやすくなります。事実、Llama 4のような早期融合モデルでは入力に与えた画像トークン列に対応する出力埋め込みが視覚的特徴を保持していると推測できるため、最終層のそれら埋め込みベクトル群を取り出すことで視覚情報を抽出します。一方、テキストトークンに対応する最終埋め込み（例えば文末の[EOS]トークンのベクトル）は言語生成に用いる、といった役割分担を明確化します。
	•	デュアルヘッド構造: 上記の区別に基づき、LLMの出力から2種類の出力ヘッドに分岐させます。それぞれは:
	•	言語出力ヘッド: 従来通りLLMの言語モデルヘッド（ボキャブラリに対する全結合層）を用いてテキストを生成します。具体的には、Llama 4の最終層出力のうちテキストトークンに対応する隠れ状態ベクトル（例えば直近のテキストトークン位置のベクトル）を用いて確率分布を算出し、次のトークンを生成する自回帰デコーダとして機能させます。これによりユーザへの回答文やキャプションなどを生成します。
	•	視覚出力ヘッド: 新たに視覚特徴専用のデコーダ/ヘッドを設け、LLMから得た視覚埋め込みを入力として画像出力を生成します。具体的には、LLM最終層から取り出した画像トークン対応の埋め込み群をさらに画像側タスク（セグメンテーションや物体検出）の入力とします。Phase3Bモデルではセグメンテーションマスク生成が主な視覚出力と想定されるため、これら埋め込みを後述のセグメンテーションヘッド（改良Mask Decoder）に渡します。こうすることで、LLM内で高次元で融合された視覚情報を専用のデコードプロセスでピクセル空間にマッピングできます。
	•	実装例: LLM統合部の処理フローを疑似コードで示します:

# 例: LLM統合と出力分離の流れ
visual_prompts = QFormer(image_feats)               # 視覚クエリを取得
input_seq = [<VISUAL_PROMPT_START>] + visual_prompts + user_text_tokens + [<END>] 
# ↑ 視覚トークンとテキストトークンを区別できる形で連結

outputs = Llama4.forward(input_seq)                # LLMへの入力（視覚+テキスト）
visual_outputs = outputs[:len(visual_prompts)]     # 出力埋め込みのうち視覚トークン分を取得
text_output_embed = outputs[-1]                    # 最後のテキストトークン(END)の隠れ状態

text_answer = LM_head(text_output_embed)           # 言語ヘッドでテキスト応答生成（次トークン予測）
mask_pred = MaskDecoder(visual_outputs, image_feats_multi)  # 視覚ヘッド（MaskDecoder）でマスク生成

上記のように、LLM出力をトークン種別でスライスし、それぞれ適切なデコーダに渡す処理を実装します。特にセグメンテーションなど視覚出力は画像エンコーダからの特徴マップも必要となるため、LLMからの視覚埋め込み（グローバルな文脈を含む特徴）と、元の画像多段特徴を組み合わせてMaskDecoderがマスクを生成する設計とします。この分離機構により、モデルはテキストと画像の両出力を同時にかつ適切に解釈して生成できるようになります。例えばユーザが画像と言語で質問した場合、LLMはテキスト回答を生成しつつ、該当する画像領域のマスクも並行して生成可能になります。これはシングルストリームのLLMだけでは困難だったタスク分離を実現し、応答の多様性と正確性を高める狙いがあります。

3. LoRAエキスパート統合によるマルチモーダル適応

《現状の課題》 現行Phase3Bモデルを新たなモダリティやタスクに適用する際、モデル全体をフルチューニングするのは計算コストが高く、またせっかくの事前学習済みモデルの汎化性能が劣化するリスクがあります。特にSAM由来の画像エンコーダやLlamaなど巨大モデルを含む場合、パラメータ数が膨大であり効率的な適応が必要です。さらに、将来的にRGB画像以外の入力（深度画像や赤外画像など）を扱うマルチモーダルセグメンテーションに発展させる場合、各モダリティの特徴分布の違いを考慮した調整が欠かせません。

《修正方針》 モデル全体の大部分を凍結し、可変部のみLoRA (Low-Rank Adaptation)モジュールによって効率的に適応させる手法を導入します ￼ ￼。具体的には、画像エンコーダ（SAMのViTバックボーン）や必要に応じてLLM内部の注意機構に対し、低次元の差分ウェイトを挿入・学習させることで、新しいデータ分布やモダリティへの追従を図ります ￼。さらに複数のLoRAモジュールをエキスパートとして用意し、入力モダリティごとに使い分けるMixture of Experts (MoE)構造を採用します ￼。この設計により、各モダリティに特化した調整を行いつつ、SAMやLLMの既存知識は保持されます。
	•	LoRAの画像エンコーダへの適用: SAMの画像エンコーダ（ViT）各層の重みに対し、LoRAユニットを組み込みます。LoRAは事前学習済み重み行列 $W$ に対し、$\Delta W = U \times V$ の形式で低ランク（例えばランク$r$）の補正行列を追加する仕組みです ￼。実装としては、各自己注意層やMLP層の重みに対し並列に低次元ボトルネック層（ダウンプロジェクション$U$とアッププロジェクション$V$）を挿入し、学習時にはこれら$U, V$のみを訓練、元の$W$は固定とします ￼。こうすることで、例えば医療画像など新ドメインに対してもごく一部のパラメータ更新で適応可能となります。なおSAM自体の強力な一般化性能は保持されるため、LoRA調整後も元の機能を大きく損なうことなく追加適応が可能です ￼。
	•	MoEルーティングの導入: 複数のLoRAエキスパートを用意し、入力モダリティや条件に応じてそれらを動的に組み合わせる仕組みを取り入れます。 ￼で述べられているように、各モダリティ専用にLoRAモジュールを訓練しておき、推論時にRouterが入力ごとの適切なエキスパートを選択・重み付け統合する戦略を採ります。例えばRGB画像・深度画像の両方を扱えるモデルとする場合、RGB担当LoRAとDepth担当LoRAの2つを用意し、Routerが「どの割合で両LoRAの補正を適用するか」を判断します ￼。Routerは各モダリティの信頼度や存在フラグ（モダリティ欠損時のハンドリングを含む）を考慮して動作し、クロスモーダルな不整合を低減するよう設計します ￼。この動的融合により、例えば深度情報が欠落した場合でもRGBエキスパートのみで対処し、逆に複数モダリティが揃っている場合は両方の情報を補完的に活かすことができます ￼ ￼。モダリティ以外にもタスク（セグメンテーション vs 質問応答など）に応じてエキスパートを切り替えることも可能な設計としておき、Phase4以降での拡張（新タスク追加など）にも耐えられる柔軟性を持たせます。
	•	LLM側の適応: 基本的にLLM（Llama 4など）は巨大モデルのため全層微調整は避け、必要に応じてLLMにもLoRAもしくはプロンプトチューニングを適用します。例えば視覚-言語出力をより綿密に連携させるには、LLMの一部注意重みにLoRAを入れ視覚入力に合わせて調整するか、あるいはシステムプロンプトに視覚情報の扱い方を学習させるようなチューニングを行います。これもPEFT (Parameter-Efficient Fine-Tuning) の一環であり、LLM本体の知識を壊さず必要最低限のパラメータで対応します ￼ ￼。もっとも、Phase3Bの範囲ではLLM側は基本凍結でも目的は達せられる想定なので、LLMへのLoRA適用は必要に応じて段階的に導入する方針とします。
	•	インターフェースと実装: LoRAモジュールは各対象層において付加的な小クラス（例えば LoRALinear 等）として実装し、推論時には $W + \Delta W$ を合成して通常の前向き計算を行います。複数LoRAエキスパートを用いる場合、Routerから得た重みで各$\Delta W$を線形結合するか、MoE方式（Top-K選択など）で特定エキスパートのみ有効化する方式を取ります。Pseudo-codeイメージ:

class LoRAExpert(nn.Module):
    def __init__(self, W_shape, rank):
        self.U = nn.Linear(W_shape[1], rank, bias=False)  # down-proj
        self.V = nn.Linear(rank, W_shape[0], bias=False)   # up-proj
    def forward(self, x): 
        return self.V(self.U(x))  # 低ランク補正

# 利用例: ViTの自己注意の投影にLoRAを適用
class AttentionWithLoRA(MultiHeadAttention):
    def __init__(self, ...):
        super().__init__(...)
        self.lora_q = LoRAExpert(W_shape=(embed_dim, embed_dim), rank=r)  # Q投影へのLoRA
        # （必要に応じてKやVにもLoRA）
    def forward(self, x):
        h = super().forward(x)  # 通常のAttention
        h += self.lora_q(x)     # LoRA補正を加算
        return h

なお、具体的なAPIでは既存のLoRA実装ライブラリを利用し、モデル定義後に特定の重み名に対しLoRAをインジェクトする方法も考えられます。

以上のLoRA+MoE導入によって、既存モデルの性能を維持したまま新たなモダリティ統合やタスク適応が可能となります。例えば本モデルを深度画像併用のセグメンテーションに拡張する場合、RGB用とDepth用のLoRAを訓練しRouterで動的融合するだけで、SAMの凍結バックボーンを流用しつつ高い精度を発揮できることが報告されています ￼ ￼。また欠損モダリティ時のロバスト性も向上し、最悪の場合でも単一モダリティで動作継続できる柔軟なモデルとなります ￼。

4. セグメンテーションヘッドのマルチスケール対応強化

《現状の課題》 現行Phase3Bモデルのセグメンテーション機能（画像中の対象領域をマスクとして切り出す処理）は、SAM由来の高レベル特徴に依存した実装になっていると推測されます。SAMのデフォルトでは画像を256×256など固定解像度に埋め込み、高層の抽象特徴からマスクデコーダで輪郭を再構成します。しかしこの手法だと微細な部分や小さな物体のマスク精度に課題が残る可能性があります。特に本モデルではインスタンスではなくセマンティックセグメンテーションへの応用も視野に入れているため、ピクセルレベルの精度向上が求められます ￼。

《修正方針》 マルチスケール特徴の活用によってセグメンテーション出力の精度を高める設計に変更します。 ￼にあるように、SAMのマスク生成パイプラインを拡張し、画像エンコーダの複数段から特徴マップを取り出して融合する戦略を取ります。具体的な変更点は以下の通りです:
	•	画像エンコーダからの多段特徴抽出: Visionエンコーダ（SAMバックボーンのViT）の中間層出力を利用できるようにします。例えばViTを数ブロックごとに区切り、それぞれの解像度の特徴（高解像度=浅い層、低解像度=深い層）を保持します。SAMでは元来最高層の特徴（極めて低い空間解像度）と言語的な位置エンコーディング等を使ってマスクを生成していましたが、本モデルでは中間の解像度の特徴（例えば16×16や32×32サイズの特徴マップ）も取り出します。これにより、細部情報（エッジやテクスチャ）は浅い層の高解像度特徴から、グローバルなセマンティクスは深い層の特徴から得ることができます。実装上は、ViTの順伝播で各ブロック出力にフックを掛けてテンソルを収集する形で対応します。なお、エンコーダ出力のマルチスケール化に伴い、後段Mask Decoderが扱えるようチャネル数調整や投影が必要なら適宜行います。
	•	Mask Decoderの拡張（Auxiliary Headの追加）: 従来のMask Decoder（以下「メインMaskDecoder」）に加え、補助的なマスク予測ヘッド（Auxiliary Decoder）を新設します ￼ ￼。メインMaskDecoderは主に深い層の特徴（低解像度でセマンティックな特徴）を入力とし、大まかなマスクを予測させます。一方Auxiliary Decoderでは浅い層の高解像度特徴を入力とし、メイン出力を補完・細密化するマスクを予測します。例えば、メインDecoderが「物体のだいたいの位置と形」を出力し、Auxiliaryが「エッジの細部や小領域の穴埋め」を出力するイメージです。最終的なマスクは両者を統合（例えばピクセルごとに平均や論理和を取る等）して得るようにします。この二段デコーダ構成は、MoE-LoRA論文でも提案されており、元のセグメンテーションヘッドを拡張して補助ヘッドでマルチスケール特徴を組み合わせることで精度向上を達成したと報告されています ￼ ￼。
	•	Mask Decoderへのテキスト条件入力（必要に応じて）: Phase3Bモデルではテキスト質問やクラス名に基づくセグメンテーションも想定されるため、MaskDecoderにテキスト条件を与える設計も検討します。SAMの設計上はポイントやバウンディングボックス、テキスト（Embedding経由）などプロンプトを埋め込む仕組みがあります ￼。本モデルでは、LLMから得た視覚埋め込み自体が画像内の関心領域を表すヒントになりますが、必要であればユーザ入力テキストをクラスラベルとしてMaskDecoder内部で活用することも可能です。例えば「犬をセグメントせよ」という指示に対し、LLMが犬に関連する視覚埋め込みを強調し、MaskDecoderがそれを受け取り犬の領域だけを抜き出す、といった連携が考えられます。実装上はMaskDecoderにテキストEmbedding用のクロスアテンション層を追加する形で対応できます（詳細はPhase3Bの範囲を超える可能性があるため付録的扱い）。
	•	インターフェースの詳細: 修正後のMask Decoderモジュールの構造を疑似コードで示します:

class MaskDecoder(nn.Module):
    def __init__(self, ...):
        # 既存のMaskDecoder構成要素 (自己注意, クロスアテンション etc.)
        # 補助デコーダ用の層を追加
        self.aux_decoder = AuxiliaryDecoder(...)
    def forward(self, feat_global: Tensor, feat_mid: Tensor, feat_high: Tensor, visual_context: Tensor) -> Tensor:
        """
        feat_global: 低解像度(深層)特徴マップ (例: 16x16)
        feat_mid: 中解像度(中層)特徴マップ (例: 32x32)
        feat_high: 高解像度(浅層)特徴マップ (例: 64x64)
        visual_context: LLMからの視覚コンテキスト埋め込み（オプション）
        """
        mask_coarse = self.main_decoder(feat_global, visual_context)       # 粗いマスク予測
        mask_refined = self.aux_decoder(feat_mid, feat_high, mask_coarse)  # 高解像度特徴で粗マスクを細密化
        final_mask = fuse(mask_coarse, mask_refined)  # 融合処理: ANDやweighted sum等
        return final_mask

上記のように、Main/Auxの両デコーダ出力を組み合わせて最終マスクを出力します。AuxiliaryDecoderは内部でfeat_midとfeat_highから詳細なエッジ情報を抽出し、mask_coarseで粗く特定された領域を精緻化するネットワークとして設計します。融合方法はシンプルには画素毎平均や、または2つのマスクをANDして共通部分を強調しつつcoarse側でカバーされた領域は残す、といった手法が考えられます。これらは実験的に最適なものを選択します。

以上の改良により、マルチスケールな文脈を考慮した高精度セグメンテーションが可能となります。MoE-LoRAの研究でも、元のSAMヘッドに補助ヘッドを加えることで様々な解像度の特徴を融合し精度改善を達成したとされています ￼。本モデルでも小さな物体や複雑な境界のセマンティックセグメンテーション性能向上が期待できます。

修正内容のまとめと実装ステップ

上記の各項目について、モジュール単位に修正点を整理し、最終的なモデルアーキテクチャ概要と実装の手順を示します。

モジュール別変更点と新インターフェース一覧
	•	Q-Former モジュール: （画像+テキスト特徴の統合抽出を担当）
	•	変更前: 画像エンコーダの出力を入力とし、固定長のクエリ特徴を出力する。テキスト入力は考慮されていない。
	•	変更後: 画像特徴に加えてオプションでテキストトークン列を受け取り、自己注意・クロスアテンションを通じて視覚と言語の融合特徴（クエリ群）を出力できるようになる。
	•	インターフェース変更: QFormer.forward(image_feats, text_tokens=None) -> query_embeds（テキスト入力がある場合は内部で注意マスクによりクエリがテキストと相互作用する ￼）。出力query_embedsは次段のLLMに接続されるベクトル群。
	•	LLM統合 (Llama 4) モジュール: （テキスト生成と言語・視覚特徴の融合を担当）
	•	変更前: 視覚情報をプロンプト（またはCross-Attention経由）としてLLMに供給し、単一系列でテキストを生成する。視覚出力用の分岐はなし。
	•	変更後: Q-Formerからの視覚クエリ埋め込みをLLMの入力トークン列に統合（BLIP-2方式ではLLMのEmbedding次元に射影し先頭に付加） ￼し、テキストトークンと一緒に処理。LLM内部は変更しないが、出力時に視覚トークン部分の隠れ状態を抽出し画像用ヘッドへ渡す機構を追加。
	•	インターフェース変更: LLM.forward(all_input_tokens) -> all_output_hidden_states（出力された隠れ状態列を、トークンID範囲で分割して利用）。LLM自体の言語モデルヘッドによるgenerate(text_hidden) -> next_tokenに加え、新設計ではvisual_head(visual_hiddens) -> image_output（例: マスクテンソル）を別途用意している。LLM本体はブラックボックス的に扱い、入出力の取り扱いを変更する形です。
	•	Vision Encoder (SAMバックボーン) モジュール: （画像から特徴マップ抽出を担当）
	•	変更前: 入力画像をパッチ化してViTでエンコードし、最終レイヤの抽象特徴（低解像度）を得る。中間特徴は未利用。
	•	変更後: ViTの中間層からも特徴を抽出（多段出力）し、Mask Decoderで利用する。エンコーダ本体の重みは基本凍結し、各層にLoRAモジュールを挿入して新ドメインの特徴差分を学習できるようにする ￼。
	•	インターフェース変更: Encoder.forward(image) -> (feat_global, feat_mid, feat_high, ...) 複数解像度の特徴を返すよう変更（必要に応じてリストや辞書形式）。内部的には例えばViTをブロック0～11まで通した後、ブロック{4,8,12}（仮）の出力をそれぞれfeat_high, feat_mid, feat_globalとして出力するなど。LoRAに関してはエンコーダ内部に組み込むためインターフェース上は明示的に出さずともよいですが、設定により有効/無効を切り替えられるようにします。例えばEncoder.train(mode, lora_enable=True)等でLoRAをオンオフできる設計も考えられます。
	•	Mask Decoder (セグメンテーション出力) モジュール: （視覚特徴からマスク画像を生成）
	•	変更前: SAMのMaskDecoderに近い構造で、高次元の画像埋め込みと位置エンコーディング、ユーザプロンプト（ポイント等）を入力にマスクを一段で生成する。
	•	変更後: MaskDecoderを拡張し、複数解像度の特徴を入力に取る設計に変更。メインDecoderに加えAuxiliary Decoderを持ち、それぞれ異なる解像度特徴からマスクを推論し融合する ￼。またLLMからの視覚コンテキスト埋め込み（該当オブジェクトに関する高次情報）が入力として追加される場合がある。
	•	インターフェース変更: MaskDecoder.forward(feat_global, feat_mid=None, feat_high=None, visual_context=None) -> mask 複数特徴マップを可変長または個別引数で受け取る形に変更。戻り値maskは画像サイズにアップサンプリングされた2値マスク（またはクラスIDごとのセマンティックマップ）。Auxiliary Decoderを内部に持つため、場合によってはforward内で2つのマスクを計算し融合する処理を行います。ユーザプロンプト（ポイントやテキストラベルなど）はvisual_contextあるいは別途プロンプト引数で受け取れるよう検討します（Phase3Bでは必須でないため簡略化も可）。

実装ステップガイド

上記の仕様に基づき、修正実装を段階的に進める手順を以下に示します。開発・改修を行う際にはこの順序で段階的にテストしながら進めることで、大規模な変更による不具合を早期に発見できます。
	1.	Q-Formerの改修: まずQ-Formerモジュールにテキスト入力対応を実装します。QFormer.forwardのシグネチャにテキストトークン引数を追加し、BLIP-2論文の設計に従ってクエリとテキストの統合動作を盛り込みます ￼。実装手順としては、既存の自己注意Transformerにテキストトークンを追加投入できるよう変更し、クエリ同士およびクエリ-テキスト間の注意マスクをタスクに応じ設定します（例えばデフォルトはテキストを参照しないが、ITMや生成時は参照する等）。次に、Q-Formerの出力（query_embeds）をLLMに渡すインターフェースを作ります。具体的には、Q-Former内またはLLMの入力組み立て部分で全結合層による次元合わせと視覚トークン連結を実装します ￼。この段階ではダミーのLLM（例えば簡易なTransformerデコーダ）を用いて入出力の形を確認し、テキストなし・あり双方でforwardが動作することをテストします。
	2.	LLM統合部の改修: 次に、Llama 4などLLMへの視覚情報入力と出力分離の仕組みを実装します。まずBLIP-2方式であれば手順1で射影・連結済みの視覚トークン付き入力をそのままLLMに与え、生成処理を行います。一方Llama 4の初期融合機構を直接使う場合でも、内部的には視覚トークン＋テキストトークンの混合シーケンス処理となる点は同じなので、実装上は大差ありません。LLMから得られた隠れ状態列について、視覚トークン部分の抽出処理を追加します。例えばvisual_embeds = outputs[:n_visual_tokens]のようにトークン数でスライスするか、埋め込みに特殊なマーカー（前述のセグメントID等）を付与して出力上でフィルタリングします。続いて、抽出したvisual_embedsをMask Decoderに渡して画像マスク出力を得る処理、および言語部分の最終隠れ状態からテキストを生成する処理を実装します。テキスト生成は既存のgenerate()関数やデコーダループを活用し、視覚マスク出力はMaskDecoderのforwardを呼び出す形にします。重要: この時点で、一連の流れ（画像+テキスト→Q-Former→LLM→テキスト+マスク出力）が動作することを統合テストします。簡易的に、入力画像に対し「背景をマスクせよ」等の指示テキストを与え、MaskDecoderの出力するマスクが画像全体になる（背景以外なし）こと、テキスト出力が合理的に生成されること等を確認します。
	3.	LoRAモジュールの組込み: モデルの大枠が動いたら、各所にLoRAによるパラメータ効率化と可搬性向上のための改修を行います。まずVision Encoder（ViT）の各ブロックにLoRAを挿入します。既存のモデル定義を拡張する形で実装する場合、各LinearレイヤーやAttentionレイヤーをラップしてLoRA付きクラスに置き換えます。実装後、学習フラグを立てた際にLoRAの重みだけが勾配更新されること、推論結果がLoRA無効時と同等になることを確認します。次に、必要であればLLM側のAttentionにもLoRAを挿入します（Phase3Bではまず画像側中心で問題ありません）。さらに、MoEルーティングを構築します。これは入力データのモダリティ情報をもとにLoRAエキスパートの重みを動的決定するコンポーネントで、例えば簡易にはone-hotなモダリティIDから対応LoRAを選択、発展的には軽量なネットワークで入力特徴を解析して各LoRAの重み係数を出力するように実装します ￼。Phase3B時点ではモダリティ数も限られるため、まずは静的に「RGBならエキスパートA、DepthならB」程度の切り替えでも構いません。Routerの出力に基づき、Encoder内で適用するLoRAの線形結合を行う処理を追加します。以上のLoRA/MoE実装後、学習ルーチンで既存重みが凍結され差分のみ学習されることをデバッガ等で確認します。また単一モダリティ（RGBのみ）入力時にはRouterの選択で正しいLoRAが当たること、別モダリティを模擬した入力でもエラーなく進むことをテストします。※モダリティ切替のテストは、実データがない場合はRGB画像を二種類読み込み「モダリティA/B」と見立てて動作確認する方法もあります。
	4.	セグメンテーションヘッドのマルチスケール拡張: Vision Encoderからの多段特徴が取得できるようになったら、Mask Decoder側を強化します。まずEncoderの中間出力を実際に得られているか確認し、それらを適切に縮小/投影してDecoderに入力できる形に整形します。MaskDecoderクラスを修正し、複数の特徴マップを受け取れるよう関数シグネチャを変更します（上記インターフェース参照）。次にAuxiliary Decoderを実装します。これはメインDecoderと類似の構造を持ちつつ、入力が高解像度特徴で出力がマスクである点が異なります。簡易に実装するには、メインDecoderのコピーを作り一部レイヤを共有または別インスタンスにする方法があります。高解像度特徴は空間サイズが大きいため、そのままでは計算量が増えすぎます。対策として、Auxiliary Decoderでは層数を減らしたり、または高解像度特徴を適度にダウンサンプル（たとえば一段畳み込みで半分解像度にする等）してから処理する実装も考えられます。メイン・補助それぞれでマスク予測後、両者を統合する処理を実装します。統合手法の一例としてはfinal_mask = sigmoid(mask_coarse) * sigmoid(mask_refined)のようにピクセル毎積（論理積に近い）を取ることで、両方で確信度の高い領域を残す方法があります。または単純平均でも動作はします。ここは開発時に数種類実装し、Validationデータで精度を見るのが望ましいです。最後に、新MaskDecoder全体を通して推論し、単一スケール版と比較してマスク境界の滑らかさや小物体検出が改善しているかを確認します。MoE-LoRA論文の結果によれば、この多スケール対応で特に困難な状況での性能が大きく向上しているため ￼、本モデルでも類似の効果が出ているか定性的・定量的に評価します。
	5.	総合テストとチューニング: すべての修正を統合したモデルについて、エンドツーエンドのテストを行います。Phase3Bの目標タスク（例: テキスト付き画像入力に対するセマンティックな質問応答＋マスク生成）を実行し、期待通りの出力が得られることを確認します。具体的には、いくつかテストシナリオを用意します:
	•	視覚質問応答シナリオ: 例：「画像中の猫は何匹いますか？」に対し、LLMが「2匹です」と回答しつつ、画像中の猫領域2箇所にマスクを出力する。
	•	指示に基づくセグメンテーションシナリオ: 例：「画像の建物部分をマスクで塗りつぶしてください」に対し、LLMは空のテキスト応答（または「塗りつぶしました」等）とともに建物領域のマスクを正確に出力する。
	•	モダリティ切替シナリオ: （もし複数モダリティを扱う場合）RGB+Depth入力のときとRGB単独のときで動作し、Depth欠損時でも大きな性能低下やエラーがないか検証する ￼。
これらを試し、不具合があればデバッグします。特にLLMとMaskDecoderの同期（LLMが長い生成をしている間にマスク生成を待つ必要があるか、非自明な場合はテキスト生成を一旦止めてマスク出力→再開などの制御も検討）など、実運用に向けた細部も調整します。

以上の修正実装により、Phase3Bモデルの根本的な設計上の欠点が解消され、視覚と言語の高度な統合と分離制御、効率的な適応、精密な出力が可能となります。これら改良はPhase3Bの範囲に留まらず、今後のPhase4以降でさらなるモダリティ追加やタスク拡大にも耐えうる拡張性・柔軟性をもたらします。実際、本仕様で参照したBLIP-2やMLE-SAM（MoE-LoRA）の手法によって、マルチモーダルAIモデルの性能と汎用性が飛躍的に向上することが報告されています ￼ ￼。同様に、本モデルもこれら最先端の設計を取り入れることで、現行課題の解決と将来的な発展の土台を築くものと期待できます。
